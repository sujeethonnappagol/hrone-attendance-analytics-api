# Employee Attendance & Analytics API

FastAPI and MongoDB implementation of the employee attendance assignment. The API contract and business rules are in
`openapi.yaml`; stored document shapes are described in `DATA_MODEL.md`.

## Setup

Requires Python 3.10 or newer and MongoDB 6.0 or newer. From this directory:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:MONGO_URI = "mongodb://localhost:27017"
$env:MONGO_DB = "attendance_db"
uvicorn app.main:app --port 8000 --reload
```

The service also loads values from a local `.env`. Keep that file private; it is ignored by Git. OpenAPI is available at
`http://127.0.0.1:8000/docs`.

The seed script is for a disposable database only: `python sample_seed.py` deletes and reloads both collections. Do not
run it against a database containing work or test records you need to retain.

## Endpoints

- `GET /health`
- `POST /employees`, `GET /employees`
- `POST /attendance/punch-in`, `POST /attendance/punch-out`, `GET /attendance`
- `PATCH /attendance/{emp_code}/{date}`
- `GET /analytics/employees/{emp_code}/monthly`
- `GET /analytics/departments/summary`
- `GET /analytics/leaderboard/late`
- `GET /analytics/departments/{department}/trend`
- `GET /admin/explain/{endpoint}`

Instants at the HTTP boundary are epoch milliseconds; dates are `YYYY-MM-DD`. Attendance is addressed by employee code
and date, not by MongoDB `_id`. MongoDB indexes are created at application startup.

## Verification

The punch-in/punch-out and regularization flows were exercised through Swagger. Focused checks cover the 10-minute grace
boundary, the 30-minute overtime threshold, half-day rounding at 4.50 hours, overnight shifts, history deltas, and
duplicate/error handling. Analytics were checked against the seeded sample data, and explain plans were checked for
index scans on their primary query surfaces. There is no automated test suite in this repository.

The configured local database contains two additional test attendance records dated `2026-10-15` for `EMP0001` and
`EMP0006`. The `EMP0001` record has a PATCH audit entry by `copilot-test`. These are test data, not part of the nine
sample documents. Preserve them unless resetting a disposable database is intended.
